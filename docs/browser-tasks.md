# 桌面浏览器第三阶段：任务积累与继续

## 使用流程

网页提问、选区提问、多页比较和表单草稿在发起时先保存任务资料，回复完成后更新结果。浏览器内的“保存任务”保留当前问题及可编辑草稿；确认填写前也保存实际选用的草稿。私密标签不进入这条资料保存流程。

“浏览任务”复用左侧列表，支持按标题、问题、回复、草稿、来源网址和正文找回。开启“搜索全部会话任务”可找其他会话的资料；打开时会生成当前会话的独立副本，原任务不被覆盖。macOS 窄屏按列表 → 详情返回，宽屏保持列表与详情双栏。

继续提问时，同来源任务的历史问题、回复和草稿会作为不可信进度资料带入本轮，帮助模型接着处理；不会把无关网页的任务带入。历史回复中的来源编号需要按网址重新核对。

任务详情显示保存时间、来源网址和资料截断状态。恢复只重新打开来源网页，已有普通标签按网址复用。浏览器保持暂停，表单旧节点清空；用户核对后点击继续，重新选择字段或文字，再发起协作。保存的资料是历史快照，不代表网站当前状态，也不是业务完成凭证。

## 跨设备继续

三端使用同一个 `connor.browser-task` 第 1 版 JSON 文件。通过“导出任务”保存文件，在另一台设备“导入任务”，查看资料后点击恢复任务网页。

这是可用的文件转移流程，**没有新增账号云同步集合或自动上传本机历史**。导出包含问题、回复、用户保存的草稿及网页资料；不打包 Cookie、站点存储、请求头或活跃节点引用。登录需要在目标设备自行完成。导入不导航、不填表、不发起模型调用；导入副本采用新编号，不覆盖既有任务。

文件最多 512 KiB，1–8 个普通 HTTP/HTTPS 来源，每个来源正文最多 12000 个 UTF-16 单位；问题最多 8000、回复最多 32000、草稿最多 16000。未知版本、额外执行字段、缺失必需字段、凭据式网址、非法编号及越界内容在写入前拒绝。UTF-8 BOM 可读取。

本地每个任务独立原子保存，含会话归属和版本号。旧版本保存或删除会报冲突，损坏文件不被空记录覆盖；打开已经删除的旧列表项也不会自动复活。删除只删除本机这份任务，已导出的副本及会话原消息仍由各自流程管理。

## 验证

三端仓库各有同一份 `browser-task-v1.json` fixture，测试恢复来源、会话隔离、全会话查找、草稿保留、冲突、损坏文件及非法导入零写入。

真实网页使用本机 HTTP fixture，模型回复使用可控事件或回调。未进行真实模型调用或外部业务提交。

macOS：`swift test --filter 'BrowserTaskStoreTests|BrowserAssistedWebToolTests|BrowserAutomationQualityAuditTests|BrowserFormAssistantTests|DefaultSearchEngineTests'`，并执行 `swift build`。有 Swift 6 的主机可运行 `python Scripts/test-browser-daily-portable.py` 单独验证实际 Foundation 策略、比较构造及任务存储；不能替代 SwiftUI/WebKit 验收。

当前开发主机为 Windows，没有 Swift/macOS SDK：已添加 Foundation 测试及原生界面实现，执行了语法解析检查，未执行 macOS 编译或原生测试。
