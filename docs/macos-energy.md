# macOS 前台能耗排查与修正

## 2026-11-24 实机热点与增量优化

本机安装版 1.0.138 启动后的两次调用栈采样分别抓到会话搜索索引重建、浏览器历史索引重建，以及 Memory OS 后台近期上下文检索。CPU 观测为 180%–269%，启动约 2 分 35 秒后仍为 202.7%。采样时主线程主要在等待；这次证据补充了下文前一轮没有现场调用栈的限制。

- **会话索引**：源数据 1,259 个会话、14,246 条消息，已提交索引只缺 4 个会话的 10 条消息，原路径却清空整个索引。启动修复现在按每个会话的消息 ID 集合、标题和源更新时间选择需要更新的完整会话；保留其他索引行，处理空会话、消息移除和已删除会话。不缩减历史正文或搜索覆盖。
- **浏览器历史索引**：启动仍读取完整历史，并对照持久索引处理新增、内容/元数据变化和删除；相同文档只因本次 indexedAt 不同，不再重写。比较保留完整文档，不能仅凭 contentHash 跳过内容变化，并统一持久化日期精度，避免每次启动误判。
- **FTS 定位**：原 `id` / `session_id UNINDEXED` 条件导致每次更新或删除扫描整张 FTS 表。新增普通 SQLite 表将标识符映射到 FTS rowid，事务内同步维护。旧索引首次升级只扫描并登记现有 rowid，不重新分词或改变 FTS 排名；显式全量重建仍可使用。
- **中文索引**：同一文档的重复中文片段只规范化一次，复用文档内 tokenizer；保留原文、语义分词、完整片段、二元/三元词和原有去重顺序，不截断正文，不共享跨线程可变 tokenizer。
- **Memory OS**：保留原候选全集、分页、排序、来源时间和 fallback 语义，使用 CROSS JOIN 固定证据 ID → span 主键 → 来源对象主键的查询顺序。避免 SQLite 的 MAX 优化从来源时间索引开始，为每条派生记录反复扫描来源；没有降低维护优先级、频率、处理额度或休眠保护。

局部性能对照：同一批 100 条真实 L2 记录的来源时间值完全一致，原查询约 2.127 秒，优化查询约 0.00185 秒。合成的 1,500 文档 FTS 中删除相同 100 条记录，约从 0.0296 秒降到 0.00309 秒，两者均剩余 1,400 条。局部计时不是整机功耗或电池续航对照；当前安装版尚未替换，不能据此声称已实测新版整体功耗下降比例。

本次验证：Swift Debug 编译通过；相关回归累计覆盖 163 项，最终均通过。覆盖旧 FTS 索引迁移、增量新增/更新/删除、未变化行保留、空会话、历史完整性、中文词项等价、搜索排名、分页、时间过滤、来源时间 fallback、取消和数据库失败回滚。首轮 161 项通过；补充数据库毫秒精度与事务回滚用例后重跑受影响搜索测试，修正毫秒用例以直接验证 SQL 时间列后该项也通过。`git diff --check` 通过。未运行全仓库测试、Release 打包或新版整机功耗对照。

## 2026-11-23 前台优化范围与证据

本轮仅减少界面的重复工作和持续装饰动画。后台记忆维护协调器及其测试已恢复到本轮优化前的版本：不改变记忆任务优先级、调度、睡眠保护、处理逻辑或持久化。健康检查恢复原有 10 秒节奏。

排查时没有找到运行中的康纳进程，因此没有获取到今天高耗电现场的调用栈，不能断言下列问题就是当天异常的全部原因，也没有实测整机功耗下降比例。

## 确认的前台开销路径

1. **跨页面的侧栏动画。** `CraftSessionRow` 对每个 emphasized/interruptive 会话启动没有终点的 900 毫秒动画循环，持续改变背景与缩放。只要侧栏行存在，聊天、浏览器和其他页面都会承担这部分动画开销。改为提示两次（四个状态转换，约 3.6 秒）后保持静态强调；保留徽标、强调色、审批和通知功能。减弱动态效果或启动提示时处于低电量模式则使用静态强调。
2. **活动摘要与明细重复计算。** 原先两个独立视图任务随事件数量/末事件变化而重启；展开时两条路径都扫描完整事件构建摘要，而且旧 detached 任务不会随着视图任务取消。改为单个构建任务：同一次结果提供摘要和明细；纯文本 token 不重启工具活动构建；工具进度、审批、压缩、完成、失败、取消和展开状态仍触发更新。行消失或任务被替换时向 detached 构建传递取消。
3. **每个 token 追加事件时的数组复制。** 原先从字典取出数组、追加、写回时，字典仍保留旧数组，会产生额外 copy-on-write 开销。现在通过字典的可变访问原地追加；保留完整事件、顺序和原 50 毫秒发布节奏。最终快照替换、会话删除、关闭时取消过期的待发布任务，避免重复发布和结束后的回写。
4. **标题装饰刷新。** 运行态标题原先使用 15 fps `TimelineView` 与渐变遮罩；现改为静态文字，继续使用既有运行状态和进度提示。
5. **滚动通知重复排队。** 同一轮 RunLoop 的多次 bounds 通知原先各自安排主线程回调，之后才去重。现在先合并排队，再读取最终几何信息；保留滚动跟随、触顶加载、会话锚点和历史消息加载策略。
6. **重复连接状态广播。** 网络路径更新、正常业务请求与健康检查不再反复发布相同的连接值；实际状态切换仍广播，探测间隔保持原 10 秒。

另保留调试卡顿采样显式启用（`CONNOR_STALL_MONITOR=1`），以及音频进度任务取消后立即退出的修正。

## 功能与回归范围

- 完整事件与最终正文仍由原有运行时产生、保存；不删除 token、工具或审批记录。
- 纯文本 token 不影响活动摘要时，仅避免重新计算；最终文本/消息边界仍触发更新。
- 侧栏提示从无限动画变为有限动画，提醒状态、通知和操作入口保留。
- 没有调整浏览器网页脚本、媒体播放、自动化协议、实时消息、同步心跳、记忆租约、导入恢复或历史消息窗口。
- 回归覆盖 token 批次完整性、最终快照、取消和关闭、活动更新触发条件、摘要状态、审批、关注状态，以及滚动指标、历史加载与锚点。

## 运行时对照测量

使用相同 Release 配置、设备、电源模式、账号和数据量；基线提交与修改版分别预热 2 分钟、测量 10 分钟，每个场景至少重复 3 次。不要把 Debug 采样和编译进程纳入结果。

| 场景 | 操作 | 观察项目 |
| --- | --- | --- |
| 前台空闲 | 侧栏保留多个需要关注的会话，停留无运行任务的页面 | 提示结束后的 CPU/GPU 时间、唤醒、是否还有连续动画 |
| 持续生成 | 使用相同输入和模型，分别收起/展开活动 | CPU 时间、摘要构建次数、工具和审批状态、完整回复 |
| 历史会话 | 查看长会话，滚动并加载更早消息 | 滚动响应、位置、消息完整性 |
| 内嵌浏览器 | 同一网页、同样媒体与标签数量 | 区分 Connor 主进程与 WebContent/GPU；区分网页工作与侧栏动画 |
| 网络与取消 | 断网恢复、取消生成、快速切换和关闭页面 | 原有探测时效、任务终止、无陈旧 UI 回写 |

使用 Instruments 的 Time Profiler、System Trace 和当前 Xcode 可用的能耗工具，结合活动监视器 CPU 时间、能耗影响。后台记忆按既有配置运行，两组测量保持相同的记忆任务负载，不通过暂停或降级记忆来获得更低数值。

## 本轮验证结果

SwiftPM Debug 编译通过；相关回归 130 项通过，1 项按原有配置跳过（维护轮询测试已标记为环境敏感）。执行范围包括前台能耗回归、连接状态发布、活动摘要、后台维护原有行为、会话运行与审批、音频、关注状态和聊天视口。未运行全量测试，未完成实机 Release 功耗对照。
