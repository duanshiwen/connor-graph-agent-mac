# 邮件内容同步 v1

更新日期：2026-10-28。

mail_accounts 已停止账号同步。邮箱名称/地址之外的登录用户名、IMAP/SMTP 主机、端口、安全模式及全部凭据只留在本机；不会因为收到邮件副本而创建一个能连接服务器的邮箱账户。历史云端配置不再下发，本机配置不被迁移或删除。

新集合是 mail_messages，载荷继续使用账号 E2EE。四端邮件页面将本机缓存与同步收到的内容统一放入邮件列表，按时间排序并去重；无需切换“跨端邮件”入口，也无需在接收端配置邮箱即可阅读。只有本机已配置且能定位到对应邮件的邮箱才提供原有邮件操作。

## 身份和去重

统一记录 ID 为 `mail_` 加以下 UTF-8 文本的完整 SHA-256 小写十六进制：

`trim(lowercase(邮箱地址)) + NUL + 文件夹 + NUL + UIDVALIDITY + NUL + UID`

INBOX 的大小写统一为 INBOX，其他文件夹保留原始名字。UIDVALIDITY、UID 来自邮箱服务器，使用正的 32 位整数标准十进制字符串；没有可靠标识的本机缓存不冒充可同步邮件。身份不包含某个客户端自己创建的账号 ID，也不依赖主题、发件时间或可能缺失/重复的 Message-ID。

同一邮箱同一文件夹同一 UID 代的邮件在两端产生相同记录 ID。后端 `(user_id, collection, record_id)` 唯一约束保证只有一条当前记录；变更日志仍可保留它的不同版本。不同文件夹是不同副本；UIDVALIDITY 改变时不把新邮件覆盖到旧邮件 ID，邮件列表默认显示该文件夹最近的有效代。

配置同一邮箱的两端仍可能各自连接 IMAP。头部/已读状态可重新检查，已完整缓存的正文会复用；跨端上传使用本机观察指纹，实际内容没变化时不因抓取时间、另一端的格式差异或重启而重复上传。

## 载荷

schemaVersion 固定为 1；所有字段由当前客户端完整编码：

| 字段 | 类型与含义 |
| --- | --- |
| id | 上述稳定记录 ID |
| mailboxAddress/mailboxName | 用于展示来源的邮箱地址/名称，不是登录配置 |
| folder/uidValidity/uid | 来源文件夹及 IMAP 邮件身份 |
| messageId | 原邮件 Message-ID 参考值，不作为唯一键 |
| subject/from/to/cc | 主题、发件人和收件人地址；to/cc 是字符串数组 |
| sentAt/updatedAt | epoch 毫秒；updatedAt 是共享内容实际变化的时钟，不能每次抓取都刷新 |
| snippet/bodyText | 摘要和纯文本正文 |
| bodyAvailable/bodyTruncated | 正文是否已经获取、来源缓存是否不完整；不能把缺少正文当作空邮件 |
| attachments | 附件描述数组：id/fileName/mimeType/size/contentId/isInline；size=-1 表示未知 |
| isRead | 已配置邮箱的源设备观察到的已读状态 |

不包含附件字节、下载地址、本地文件路径、原始 MIME、邮箱服务器配置或任何凭据。解码后通过白名单 DTO 重新编码，未知的 password、imapHost、attachment.data、localPath 等字段不会进入本地副本及后续投影。邮件 HTML 在邮件详情中以纯文本显示，不执行邮件中的脚本或加载远程图片。

源设备只共享已经获取的邮件；不会为了账号同步强制下载全部历史。Mac 既有正文回填完成后会继续共享正文；其他平台也复用完整缓存，正文未取得时明确显示待获取状态。附件下载、回复和发送仍需要本机配置与授权；仅有同步内容的邮件不提供代理邮箱操作。

## 合并和传输

元数据使用 updatedAt 合并，相同时间以内容指纹确定胜者。缺失/截断正文不能覆盖已有完整正文；同一 UID 代中缺失的正文或附件描述不能把已有内容清空。缓存清理、退订邮箱不会作为全局邮件删除传播。

每台设备另存它上次实际观察的内容指纹，不包含抓取时间。这个指纹不通过账号同步传输；收到另一端的文本表示后，本机未变化的原观察不会形成回推循环。

正文超过 512 KiB 时，在 mail_messages 内复用分块传输 v1：每块最多 256 KiB，最多 512 块。信封仍使用 _connorSessionChunks/_connorSessionChunk 历史键名，解码必须选择邮件协议。根和所有块分别加密，以各自集合和记录 ID 绑定 AAD。只有字节长度、SHA-256、邮件 ID 和语义哈希均通过后才应用，块不会显示成邮件。

邮件语义哈希遍历完整 JSON 值，向 SHA-256 输入一串长度前缀 token。每个 token 是 4 字节无符号大端 UTF-8 字节长度及 UTF-8 内容。对象输入 o、成员数量，再按键排序输入每个键及值；数组输入 a、元素数量及有序元素；字符串输入 s、原文；布尔输入 b、1 或 0；整数输入 n、十进制值；null 输入 z。此规则消除 JSON 键顺序、Unicode 转义和整数编码差异。更新时间参与传输比较，本机观察指纹则把 updatedAt 置 0。

同会话传输一样，超出 128 MiB 的单条内容保持待同步，其他记录继续；旧块暂不自动回收。接收与本机投影/上传失败相互独立，缺块持久化等待重试。
